# ADR 0002：M1設計判断と未検証の選定
日付：2026-11-14
状態：以下の確定事項はユーザーの本作業依頼による承認。文書のmain統合は別承認待ち。
参照：requirements v0.1と変更履歴、ADR 0001、m1-domain-design.md D01〜D08、Issue #3、参照会話「構想を聞く」。

## 確定事項
- D01/D02：expertはActorの専門性・役割。基本種別はperson / organization / government-body。行政は独立主体。団体未所属の個人も活動を提案できる。
- 各Caseは一活動のみ参照し、複数活動横断CaseはM1対象外。一活動に複数Case、各Caseに複数模擬Actorを関連付ける。
- UserAccountとActorを別管理。公開の所属記述は代理操作権限を与えない。
- D03：CasePartyは模擬Actorのみ。公開活動の参照は読取参照であり参加・同意を意味しない。
- D05：位置精度、公開粒度、取得根拠を別管理。欠損は欠損のまま保持する。
- D06/D07：自己審査は原則禁止。作成者・重要変更操作者・案件当事者を操作するアカウントは当該版を承認できない。M1で例外経路を設けない。サーバー側で権限・版を検証する。
- 関係者、参加条件、重要な必要資源の変更は再審査。承認を案件版に固定し、重要性を判定できない変更は再審査側へ倒す。詳細な差分規則は#7でテストする。
- 実AI・外部連絡・実合意・M2以降の機能は導入しない。M0互換APIは維持し、本番認証保証とは扱わない。

## 選定候補と根拠・リスク（未確定）
|候補|根拠|リスク・確定前の検証|
|---|---|---|
|Drizzle（第一候補）|TypeScriptでスキーマを記述しSQLに近い操作が可能。domain外のアダプターに限定しやすい|PostGIS geography、ロール、追記制約、移行再適用を実DBで検証。未導入|
|pg + 明示SQL（比較候補）|M0でpgを使用。PostGISと権限DDLを直接記述可能|型とDDLの整合性・移行履歴の管理負担。Drizzleを自動的に置換しない|
|Auth.js（比較候補）|JWT/DBセッション戦略を比較でき、既存Next.js側の認証境界候補|SDKの版互換、失効、CSRF、アカウント紐付け、権限失効を未検証|
|Supabase Auth（比較候補）|認証サーバー・JWTを使う構成を提供|外部運用依存とJWT/RLS/アプリ認可の責務整合、費用・保管場所を未検証|
認証製品の決定は#7で実験後。SDKの本人確認と案件権限を混同しない。#4はSDK非依存の最小契約に限定できる。

## 未確定事項

Q03：実在データの調査対象・利用条件・具体的公開粒度・機微情報・保存期間は未確定。実在データを収集しない。
Q04：面表現、条件必須項目と重要資源判定の詳細は#6/#7で具体化。
#3全項目の選定完了やM1完了は主張しない。
